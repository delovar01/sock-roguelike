# Алгоритмы

В игре используются три алгоритма из разных областей.

## 1. BSP-генерация подземелья (Сложный)

Файл: `src/algorithms/bsp_dungeon.py`.

**Зачем.** Для рогалика нужны разные уровни при каждом прохождении.
Случайное блуждание даёт пещеры, клеточные автоматы — гладкие пещеры,
а нам нужны прямоугольные комнаты с коридорами — как в Binding of Isaac
или Enter the Gungeon. Это умеет BSP.

**Идея.** Берём весь прямоугольник уровня, рекурсивно делим его
пополам по случайной оси, пока куски не станут достаточно маленькими.
Получаем дерево, в листьях — прямоугольные области. В каждом листе
делаем комнату — прямоугольник чуть меньше области. Затем проходим
по дереву и соединяем комнаты соседних поддеревьев L-образными
коридорами.

**Этапы (раздельные функции):**

1. `split_node(node, rng, depth)` — рекурсивное разбиение.
   Делим по длинной стороне, чтобы не было длинных узких полос.
2. `fill_rooms(node, rng)` → `create_room_in_leaf(...)` — комнаты в
   листьях со случайным размером и положением.
3. `carve_rooms_to_grid(...)` — переносим прямоугольники комнат на
   сетку как пол.
4. `connect_rooms(node, grid, rng)` → `carve_l_corridor(...)` — снизу
   вверх по дереву соединяем комнаты пары поддеревьев.

**Вход:** `width`, `height`, `seed`.
**Выход:** двумерный список `TileType.WALL / FLOOR / EXIT`, а также
позиции входа и выхода.

**Сложность.** O(n) по времени и памяти, где n = width × height.
Каждая клетка сетки пишется максимум константное число раз
(пол комнаты, потом, возможно, пол коридора).

**Детерминизм.** Все случайные решения берутся из одного `random.Random(seed)`,
поэтому при одинаковом seed получаем одинаковую карту — это используется
для сохранений (храним только seed уровня, а карту восстанавливаем).

## 2. A* поиск пути (Лёгкий)

Файл: `src/algorithms/a_star.py`.

**Зачем.** Моль должна догонять игрока кратчайшим путём, обходя стены.

**Почему не Дейкстра?** Дейкстра расширяет волну во все стороны
равномерно. Если цель справа, он всё равно проверит всё что слева. A*
добавляет эвристику `h` (манхэттенское расстояние до цели), и волна
идёт в сторону цели. Приоритет вершины `f = g + h`, где `g` — реальная
стоимость от старта, `h` — оценка остатка.

**Эвристика.** Манхэттенское расстояние `|x1 - x2| + |y1 - y2|`. Для
тайловой сетки без диагоналей — допустимая (не переоценивает), значит
A* находит оптимальный путь.

**Реализация.** Приоритетная очередь через `heapq`, словари `came_from`
и `g_score`. По 4 соседям (без диагоналей).

**Вход:** уровень (с методом `is_walkable`), стартовый тайл, целевой.
**Выход:** список тайлов пути (без стартового), или пустой список если
пути нет.

**Сложность.** O(E log V), где V — клетки сетки, E — переходы. На
сетке 40×30 это ~1200 вершин и ~4800 переходов — путь находится
быстро.

## 3. FSM врага (Ультра-лёгкий)

Файл: `src/entities/enemy.py`, состояния — `EnemyState` из
`src/core/constants.py`.

**Зачем.** Поведение моли: патрулирует, видит игрока — преследует,
теряет — возвращается. Без FSM это превратилось бы в спагетти из
if-else.

**Состояния и переходы:**

- `PATROL` — двигается между двумя точками (углы комнаты).
  - `PATROL → CHASE`, если расстояние до игрока ≤ `DETECT_RADIUS` (5 тайлов).
- `CHASE` — путь от A*, идём по нему.
  - `CHASE → RETURN`, если расстояние > `LOSE_RADIUS` (8 тайлов).
- `RETURN` — идёт к ближайшему waypoint.
  - `RETURN → PATROL`, когда дошёл до точки.

**Гистерезис.** Радиусы детекта (5) и потери (8) разные специально:
если они равны, моль будет дёргаться между Patrol и Chase, когда игрок
стоит на границе. С разными радиусами этого нет.

**Сложность.** O(1) на одно обновление — только проверка дистанции.
Сам A* вызывается только в Chase и не на каждый кадр, а раз в 0.25
секунды — это оптимизация, чтобы не дёргать heapq на каждый тик.
