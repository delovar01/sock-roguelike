Руководство по коду «Носок-одиночка»

Этот файл — карта твоего проекта. Открывай его в браузере и читай сверху вниз. Каждый раздел отвечает на простой вопрос: «А что это вообще делает?». В конце есть шпаргалка с готовыми ответами на типовые вопросы преподавателя.

1. Что это такое

Маленький top-down roguelike. Носок-герой ищет свою пару в трубах стиральной машины. Три уровня, врага рубишь шагом-в-него (bump attack), на каждом уровне нужно найти ключ и дойти до выхода.

Технологии:

  • Python 3.12
  • pygame 2.5.2 — окно, события, отрисовка, звук
  • pytest 8.0 — тесты

2. С чего начать

Открой эти файлы в таком порядке, и всё станет понятно:

  1. main.py — 5 строк, точка входа. Просто создаёт Game и зовёт run().
  2. src/core/game.py — главный объект, цикл игры (60 раз в секунду).
  3. src/core/constants.py — все числа в одном месте: размер окна, цвета, скорости.
  4. src/scenes/game_scene.py — основная сцена игры. Здесь живёт вся игровая логика.
  5. src/algorithms/bsp_dungeon.py — сложный алгоритм, ради которого мы получаем 15 баллов.
Совет: НЕ читай весь код подряд. Открой main.py, прочитай 5 строк, потом сразу прыгай в Game.run(). Дальше по ссылкам.

4. Как работает один кадр

Игра — это бесконечный цикл, который крутится 60 раз в секунду. Один проход цикла — один «кадр». Что происходит за кадр:

1. tick(60) — pygame ждёт чтобы получилось ровно 60 FPS, считает dt (секунды от прошлого кадра)
2. обработка событий — закрытие окна, нажатия клавиш Esc/F3/Space
3. input_manager.update(dt) — смотрит зажатые WASD/стрелки, выставляет move_cmd
4. scene.update(dt) — основная логика этого кадра (см. ниже)
5. screen.fill(BG_COLOR) — чистим экран
6. scene.draw(screen) — рисуем всё
7. display.flip() — показываем кадр игроку
8. _apply_scene_change() — если сцена сменилась (например игрок выиграл)

А что внутри scene.update(dt) у GameScene? Это «канонический порядок систем» из методички:

1. Input — взяли move_cmd из input_manager
2. Movement игрока — попытка шагнуть
   └─ Если в той клетке враг — bump attack (вместо движения бьём)
3. Collision — игрок встал на предмет? на выход?
4. AI — обновили автоматы врагов, дёрнули A* в Chase, двинули их
5. Collision снова — теперь после хода врагов
6. Logic — таймер неуязвимости, время уровня

5. Каждый файл по порядку

main.py

from src.core.game import Game

if __name__ == "__main__":
    Game().run()

5 строк. Создаёт Game, зовёт run(). Всё.

src/core/constants.py

Все числа в одном месте. Размер окна, тайлов, скорости, цвета, пути к файлам, enum-ы типов тайлов / состояний врага / id сцен. Когда хочешь что-то подкрутить — иди сюда.

Почему в одном месте? Принцип чистоты из критериев (3 балла): не должно быть «магических чисел» в коде. Всё именованное.

src/core/game.py — главный класс

Game — это «корневой» объект. Внутри:

  • screen — окно pygame
  • clock — измеряет FPS
  • event_bus — общая шина событий
  • input_manager — клавиатура
  • resources — звуки и шрифты
  • _scene — активная сцена (Menu/Game/Death/Win)

run() — это тот самый бесконечный цикл (см. раздел 4).

change_scene(id) — отложенно меняет сцену (после конца текущего тика, чтобы не сломать обход).

src/core/event_bus.py — шина событий

class EventBus:
    def __init__(self):
        self.subs = {}

    def subscribe(self, name, callback):
        if name not in self.subs:
            self.subs[name] = []
        self.subs[name].append(callback)

    def emit(self, name):
        for cb in self.subs.get(name, []):
            cb()

Это паттерн Observer. Кто-то «эмитит» (выпускает) событие, кто-то на него «подписан». Никто никого не знает напрямую.

У нас 5 событий:

  • item_picked — подобрали предмет (играет звук)
  • player_attacked — игрок ударил (играет звук удара)
  • enemy_killed — враг убит (играет звук, +50 очков)
  • player_died — HP=0 (переход в DeathScene)
  • level_completed — дошли до выхода (следующий уровень или WinScene)

src/core/input_manager.py — клавиатура

Один класс. Каждый кадр update(dt) смотрит зажаты ли WASD/стрелки:

  • Первый раз направление зажато — сразу move_cmd = (dx, dy)
  • Ждём 0.18 секунды (HOLD_DELAY)
  • Потом каждые 0.08 секунды — снова move_cmd

Это и есть «зажми клавишу — двигайся». Esc, Space, F3 обрабатываются отдельно — у них автоповтора нет.

src/core/resource_manager.py

Кеш. Один раз загрузил звук — лежит в словаре, второй раз грузить не надо. Тут же музыка через pygame.mixer.music.

src/scenes/base_scene.py

Простой базовый класс с тремя методами: handle_event, update, draw. Все сцены наследуют его и переопределяют эти методы.

src/scenes/menu_scene.py

Главное меню. Кнопки «Новая игра», «Продолжить» (если есть сохранение), «Выход». Сверху — сюжетный текст из assets/story/intro.txt.

src/scenes/game_scene.py — ГЛАВНАЯ сцена

Самый большой файл. Внутри:

  • _spawn_enemies_and_items — расставляет врагов и предметы по комнатам (первый предмет всегда ключ)
  • _init_level — генерирует уровень через BSP, создаёт игрока, врагов, предметы
  • handle_event — Esc (пауза), Space (удар), F3 (debug)
  • update — главная логика кадра (см. раздел 4)
  • _after_player_move — что делать после успешного шага: подбор, пересечения, проверка выхода (с ключом)
  • _save — JSON-сохранение всего состояния
  • _draw_pause — затемнение и меню паузы

src/scenes/death_scene.py / win_scene.py

DeathScene — простая. WinScene принимает stats и выводит итоговый счёт, убитых врагов, время.

src/entities/entity.py — базовый класс

Хранит позицию в тайлах (не пикселях), цвет, флаг alive. Метод draw рисует прямоугольник со смещением камеры. Все игровые объекты наследуют его.

src/entities/player.py — носок

Главное:

  • _hp с подчёркиванием — «приватное» поле. Снаружи доступ только через @property hp (геттер без сеттера). Это и есть инкапсуляция.
  • take_damage(amount) — единственный способ уменьшить HP
  • heal(amount) — добавить HP до максимума
  • attack_damage — растёт от иголок
  • score, kills — копятся за игру
  • has_key — сбрасывается на каждом уровне

src/entities/enemy.py — моль и паук

Класс Enemy — моль. Хранит HP, состояние FSM (state = PATROL/CHASE/RETURN), путь от A*, waypoints патруля.

Класс Spider(Enemy) — наследник. Передаёт другие параметры в super().__init__: меньше HP, меньше радиус видимости, быстрее. Никаких других отличий не нужно — это пример полиморфизма.

src/entities/item.py — предметы

Базовый Item с методом on_pickup(player). Каждый подкласс делает своё:

  • Button (пуговица) — player.heal(1) + очки
  • Needle (иголка) — player.add_attack(1) + очки
  • Key (ключ) — player.has_key = True + очки

В CollisionSystem нет ни одного isinstance — она просто зовёт item.on_pickup(player).

src/systems/movement_system.py

Двигает игрока на одну клетку с проверкой level.is_walkable. Шагает врагов к waypoint или по пути от A*.

src/systems/collision_system.py

Три метода:

  • check_player_items — игрок встал на предмет? вызвать on_pickup
  • check_player_enemies — игрок столкнулся с врагом? игрок теряет HP
  • player_attack — Space: бьём всех в 4 соседних клетках
  • bump_attack — шагнул на врага = удар вместо движения

src/systems/ai_system.py

Каждый кадр для каждого врага:

  1. Обновить FSM (по расстоянию до игрока)
  2. Если в Chase — раз в 0.25с вызвать A* и обновить путь
  3. Если можно сделать шаг (по таймеру move_period) — шагнуть

src/systems/render_system.py

Рисует уровень, сущности, HP-полоски над ранеными врагами. В debug-режиме (F3) добавляет хитбоксы, цвет состояния, путь A*, FPS.

src/algorithms/bsp_dungeon.py — СЛОЖНЫЙ АЛГОРИТМ

Ради него 15 баллов. Состоит из 4 функций:

  1. split_node — рекурсивно делит прямоугольник пополам
  2. make_rooms — в каждом листе дерева размещает комнату
  3. carve_rooms — переносит комнаты на сетку как пол
  4. connect_tree — снизу вверх соединяет комнаты L-коридорами

Главная функция generate(width, height, seed) вызывает их по порядку и возвращает grid, точку старта, выхода, список комнат.

src/algorithms/a_star.py

Поиск кратчайшего пути на тайловой сетке. Приоритетная очередь через heapq, эвристика — манхэттенское расстояние. Возвращает список тайлов от старта до цели.

src/world/level.py

Хранит grid — список списков TileType. Метод is_walkable(tx, ty) — можно ли туда шагнуть. get_tile с защитой: за границами возвращает стену (никаких IndexError).

src/world/camera.py

Простая 2D-камера. follow(tx, ty) — поставить цель в центр экрана. _clamp — не выезжать за края уровня. Все объекты рисуются со смещением x - camera.offset_x.

src/ui/hud.py

Полоска HP (три квадратика), счётчик пуговиц, урон, ключ, уровень, очки, время, временные сообщения. Всё одним методом draw.

src/persistence/save_manager.py

Три функции: save_game(...), load_game(), delete_save(). JSON в saves/slot1.json.

6. Алгоритмы простыми словами

BSP-генерация подземелья

Представь лист бумаги. Ты делишь его пополам — получилось два листка. Каждый делишь пополам — получилось четыре. И так пока листки не станут маленькими (≥ 7×7 тайлов).

На каждом маленьком листке рисуешь комнату чуть меньше его размера. Потом снизу вверх соединяешь соседние комнаты L-образными коридорами.

Получается подземелье как в Binding of Isaac — комнаты разного размера, соединённые туннелями.

Сложность: O(n) по числу клеток (каждая пишется максимум константное число раз).

A* поиск пути

Это «улучшенный Дейкстра». Дейкстра рассылает волну во все стороны — расточительно. A* добавляет подсказку h — оценку «сколько ещё до цели» (манхэттенское расстояние). Берём вершины с наименьшим f = g + h, где g — пройденный путь.

В результате волна идёт прямо в сторону цели, обходя стены.

Сложность: O(E log V), где V — клетки, E — переходы.

FSM (конечный автомат) врага

У моли три состояния: PATROL, CHASE, RETURN.

ИзВКогда
PATROLCHASEигрок ближе 5 клеток
CHASERETURNигрок дальше 8 клеток
RETURNPATROLдошли до waypoint

Гистерезис: радиус обнаружения 5, радиус потери 8. Разные специально, чтобы враг не дёргался между состояниями на границе.

7. SOLID на твоих файлах

ПринципГде в коде
S Single Responsibility
(каждый класс — одна задача)		 MovementSystem только двигает. CollisionSystem только пересечения. RenderSystem только рисует.
O Open/Closed
(открыт для расширения, закрыт для модификации)		 Добавить нового врага = создать подкласс Enemy. Системы не меняем. Пример: Spider.
L Liskov
(подкласс работает везде где базовый)		 AISystem работает с Enemy и Spider одинаково.
I Interface Segregation
(узкие интерфейсы)		 BaseScene — три метода и всё.
D Dependency Inversion
(зависим от абстракций)		 AISystem(pathfinder) — поисковик пути передаётся как параметр, можно подменить.

8. Шпаргалка на защиту

Вопрос Ответ
Какая архитектура? MVC-подобная. entities + world = Model, render_system + ui = View, movement/ai/collision = Controller.
Где инкапсуляция? Player._hp с подчёркиванием, доступ через @property hp без сеттера. Менять HP можно только через take_damage и heal.
Где полиморфизм? Spider(Enemy) — наследник, переопределяет только __init__. Button/Needle/Key переопределяют on_pickup. Системы работают с базовыми классами без isinstance.
Сложный алгоритм? BSP-генерация подземелья. 4 функции: split, make_rooms, carve_rooms, connect_tree. Сложность O(n).
Почему A* а не Дейкстра? Дейкстра ищет пути ко всем вершинам — расточительно, если нужна одна цель. A* добавляет эвристику (манхэттен) и направляет волну к цели. f = g + h.
Что такое seed? Начальное число генератора случайных чисел. random.Random(seed) с одним seed всегда даёт ту же последовательность. Поэтому сохранение хранит только seed, а карту восстанавливаем при загрузке.
Что такое гистерезис в FSM? Разные пороги для перехода туда и обратно. У моли: обнаружение на 5, потеря на 8. Если бы было одинаково — враг дёргался бы на границе.
Зачем event_bus? Слабая связь. Player не знает что HUD, звук и GameScene его слушают. Pub/Sub паттерн.
Что в паузе? Esc — продолжить, Q — в меню (сохранится), + / - — громкость музыки.
Магические числа? Все в core/constants.py. Плюс Enum для типов тайлов и состояний врагов.
Что показывает F3? Хитбоксы (белая рамка), цвет состояния (зелёный/жёлтый/синий), путь A* (красные точки), FPS.
Как двигаются враги? Каждый кадр AI обновляет состояние. В Chase раз в 0.25с вызывается A*. Сам шаг — раз в 0.35с (моль) или 0.22с (паук).
Как добавить нового врага? Создаю class Beetle(Enemy): в enemy.py, в __init__ передаю свои параметры в super(). Системы трогать не надо.

9. Как запускать и тестировать

Запуск игры

python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python main.py

Запуск тестов

pytest tests/ -v

Должно быть «27 passed» примерно за секунду.
